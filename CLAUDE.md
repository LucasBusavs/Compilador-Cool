# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A COOL compiler for the PUC Minas Compilers course (2026.2), built one phase per assignment in C++:
`PA2/` = lexer (Flex, current), then `PA3/` parser (Bison), `PA4/` semantic analysis and `PA5/` codegen.
Team of 3, referred to only by role (P1 core/integrator, P2 strings, P3 comments/QA). The TP02 deadline is
2026-09-20 23:59. Project docs are in Portuguese; keep new docs in Portuguese. Open questions and every
decision taken so far are in `PA2/docs/QUESTIONS.md` and `PA2/docs/DECISIONS.md`.

Source of truth, in priority order: assignment PDF → COOL Reference Manual (Section 10 / Figure 1) → the
course's official files → `PA2/docs/DECISIONS.md`. On a conflict, record it in `DECISIONS.md` (section
"Conflitos registrados") before implementing.

## Official infrastructure

The course package `x86_64.u` (from Canvas) must be installed in `/var/tmp/cool` on Linux/WSL. Full setup,
run instructions and troubleshooting are in `PA2/docs/SETUP.md`. Dependencies are
`g++ make csh sharutils flex bison libfl-dev`, and the officially validated OS is Ubuntu 16.04. Inside
`PA2/`, this command creates the working files:

```bash
make -f /var/tmp/cool/assignments/PA2/Makefile
```

- Editable copies: `cool.flex` (the whole scanner, including helpers), `test.cl` and the end of `README`
  (the graded write-up). These are the only files we version from the infrastructure.
- Read-only symlinks, which are gitignored and must never be edited or copied: `Makefile`, `lextest.cc`,
  `utilities.cc`, `stringtab.cc`, `handle_flags.cc`, `mycoolc`, `parser`, `semant`, `cgen`.
- Headers (`cool-parse.h`, `stringtab.h`, …) stay in `/var/tmp/cool/include/PA2` and are found via `-I`.
- Reference lexer: `/var/tmp/cool/lib/.x86_64/lexer`, the default test oracle. Where it disagrees with the
  assignment text, **the assignment text wins** (D014 in `docs/DECISIONS.md`): no trailing period in
  `String contains null character`, the same message for an escaped NUL, and `String constant too long`
  even when the string ends in an unescaped newline. Those cases have hand-written `.out` files.

Build and run on Linux, with the clone in `~/`, not on Windows/OneDrive.

## Commands (from `PA2/`, once the infrastructure is present)

```bash
make lexer                                  # build the scanner
./lexer file.cl                             # print "#line TOKEN value" per token
scripts/run_tests.sh                        # diff every tests/cases/**/*.cl against the reference lexer
scripts/run_tests.sh tests/cases/strings    # one category (or single files)
/var/tmp/cool/lib/.x86_64/lexer file.cl     # reference output for one file
./mycoolc file.cl                           # our lexer + reference parser/semant/cgen
scripts/gen_cases.sh                        # regenerate byte-exact *.gen.cl cases
make submit-clean                           # before packaging PA2.u (see docs/MILESTONES.md M6)
```

## Scanner contract (see `PA2/docs/ARCHITECTURE.md`)

- Errors are returned, never printed: token `ERROR`, message in `cool_yylval.error_msg`. The exact message
  strings are listed in `docs/REQUIREMENTS.md`. String errors (too long / null) are returned as soon as
  they're detected; the `STRING_ERROR` state then discards the rest of the string.
- `TYPEID`/`OBJECTID`/`INT_CONST`/`STR_CONST` → `cool_yylval.symbol` via `idtable`/`inttable`/`stringtable`.
  `BOOL_CONST` → `cool_yylval.boolean`.
- Exclusive states `COMMENT`, `STRING`, `STRING_ERROR`, each with its own catch-all rule and `<<EOF>>` rule.
  After an EOF error, go back to INITIAL so the next call returns 0 and doesn't loop forever.
- `curr_lineno` is incremented only by the rule that consumes a `\n`.
- Rule order matters (longest match, then first rule wins). Don't reorder rules for looks.
- `cool.flex` is split into sections owned by different people (CORE/FALLBACK = P1, STRINGS = P2,
  COMMENTS = P3). Keep changes inside the section the task is about.
- Use the skeleton's own names (`string_buf`, `MAX_STR_CONST`, …). Don't invent parallel ones.

## Tests

`PA2/tests/cases/<category>/*.cl`: one small, focused file per case. Expected behaviour is described in
`PA2/docs/TEST_PLAN.md`. `*.gen.cl` files are binary (NUL bytes, no trailing newline) and generated by
`scripts/gen_cases.sh`: edit the script, not the files. `.gitattributes` forces LF; CRLF would change
string and line-count results.

## Git

Branches `feature/core-scanner`, `feature/strings`, `feature/comments`; every change reaches `main` through
a PR (review recommended, required when touching another role's section); `main` must always compile;
only the integrator merges. Conventional commits (`feat:`, `fix:`, `test:`, `docs:`, `chore:`).
Never commit `cool-lex.cc`, `lexer`, `*.o`, `PA2.u` or the infrastructure's symlinks.
